H11 · הירו צילום רחב למעלה וטקסט מתחתיו

הירו CSS · JS הירו ופתיחהתמונות וגלריות ממתין

צילום רחב שתופס את החלק העליון של המסך עד הקצוות, ומתחתיו שורת טקסט על משטח נקי: כותרת גדולה בצד אחד, משפט וכפתור בצד השני. הצילום נחשף מלמעלה למטה ונושם, והכותרת עולה אחריו.

מתי משתמשים: עסק שהצילום שלו רחב ושקט: מטבחים, נגרות, קבלן, נדל״ן, תיירות, אדריכלות נוף. מתאים כשהטקסט לא צריך לשבת על התמונה. לא לצילום אנכי או לצילום עם הרבה פרטים בתחתית.

מטבח שמתוכנן סביב הדרך שבה אתם מבשלים

מדידה אצלכם בבית, הדמיה תוך שבוע, ייצור בנגרייה שלנו והתקנה ביום אחד. בלי קבלני משנה.

לתיאום מדידה בבית
זה המבנה שהתורה רשמה כ"עוד אין לו דמו": ויז'ואל מוצמד למעלה וטקסט מתחתיו. היתרון הוא שהטקסט לא יושב על התמונה, ולכן אין צורך בשכבת קריאות על הכותרת ואפשר לבחור צילום בלי "שמיים ריקים" בשביל הטקסט. השורה העליונה כן יושבת על הצילום, ולכן יש גרדיאנט קצר מלמעלה (128 פיקסלים) רק בשבילה. השורות בגריד: הצילום מקבל את מה שנשאר (minmax(0,1fr)) אחרי שורת הטקסט, וכך כל המבנה נכנס במסך הראשון בכל גובה. הצילום נחשף ב-clip-path מלמעלה למטה תוך שהוא נושם מ-108% ל-100, ושורת הטקסט עולה אחריו (--i 2 עד 5), כי הוא הדבר הכבד. בטלפון הצילום עובר ליחס 4:3 והטקסט נערם. פתיחת העמוד (motion.md 2): ההירו מוסתר רק מאחורי html.open-anim, שהשורה הראשונה במארקאפ קובעת רק כשתנועה מותרת (בפרויקט היא עוברת ל-head). בלי JS הכל גלוי, ואם הסקריפט לא רץ ה-CSS מציג הכל אחרי 2.5 שניות. בעמוד עם הדר קובעים --t0 של 0.2 שניות כדי שההדר ייכנס ראשון, ומקצרים כך שהפתיחה כולה לא עוברת 1.2 שניות. המסך הראשון בפרויקט: min-height:100svh, תוכן ממורכז לגובה וריפוד עליון בגובה ההדר; hero-fit ו-hero-vcenter מכריעים, לא הגובה של הדמו.

קוד להדבקה

הקוד כאן עומד בפני עצמו. כל טוקן עיצוב נושא ברירת מחדל, מחלקות העזר של המאגר מוטמעות בו, ותגי הסקריפט מסודרים לפי הסדר הנכון. פרויקט שמגדיר --accent או --line משלו יורש אותם אוטומטית. הרכיב הזה מסתמך על dir="rtl".

// in view = fire. Measured directly on scroll and resize, not through IntersectionObserver:
// an observer does not update while the tab is throttled (and on a real site the hero is usually
// on screen at load anyway), and an entrance that never fires leaves the hero invisible.
function inView(el,f){
  var ro;
  function chk(){
    var r=el.getBoundingClientRect();
    if(r.top<innerHeight*.9&&r.bottom>0){off();f();}
  }
  function off(){removeEventListener("scroll",chk);removeEventListener("resize",chk);if(ro)ro.disconnect();}
  addEventListener("scroll",chk,{passive:true}); addEventListener("resize",chk);
  // a layout change with no scroll (a bar above it closes, a font swaps in) can also bring it into view
  if(window.ResizeObserver){ro=new ResizeObserver(chk);ro.observe(document.body);}
  requestAnimationFrame(chk); setTimeout(chk,300);
}
function enter(root){
  var els=root.querySelectorAll(".rv");
  els.forEach(function(el,i){if(!el.style.getPropertyValue("--i"))el.style.setProperty("--i",i);});
  // a script that ran late, after the 2.5s CSS failsafe already showed the hero: keep it shown, no second entrance
  if(els.length&&getComputedStyle(els[0]).opacity==="1")root.classList.add("is-in");
  root.classList.add("rv-on");
  inView(root,function(){root.classList.add("is-in");});
}
