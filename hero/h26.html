H26 · הירו כותרת שחוצה את הצילום

הירו CSS · JS הירו ופתיחהטקסט וכותרותתמונות וגלריות ממתין

צילום גבוה בצד אחד, וכותרת גדולה שמתחילה בתוכו ויוצאת ממנו אל הרקע: מה שעל הצילום בהיר, ומה שמחוצה לו כהה, באותה שורה. המשפט והכפתורים יושבים מתחת, בצד הפנוי.

מתי משתמשים: עסק שמוכר חוויה או מקום ויש לו צילום אחד חזק וכהה מספיק: סיורים, מסעדה, מלון, צלם, סטודיו, אדריכלות, אירועים. נראה כמו שער של מגזין ולא כמו תבנית. לא לצילום בהיר ועמוס, שהטקסט הבהיר לא נקרא עליו, ולא לכותרת של יותר משתי שורות קצרות.

לבחירת תאריךהמסלולים

יוצאים כל ערב חוץ משבתביטול בלי עלות עד יום לפני

הכותרת מצוירת פעמיים באותה תיבה בדיוק (שתי שכבות באותו תא גריד), ולכן השורות נשברות באותו מקום: העותק הכהה נחתך מחוץ לצילום והעותק הבהיר נחתך אל תוכו (clip-path עם אותו --pw של רוחב הצילום), כך שהאותיות מחליפות צבע בדיוק בקצה. שתי השכבות נכתבות מאותו מקור (בפרויקט: אותה קומפוננטה עם אותם נתונים), והבהירה מוסתרת מקורא מסך ו-inert, כך שאין כפתורים כפולים בטאב ואין טקסט שנקרא פעמיים; החצייה היא CSS בלבד, ולכן היא שלמה גם בלי JS. הכותרת מתחילה בתוך הצילום, ולכן כל שורה חוצה את הקצה; שתי שורות קצרות שלא נשברות (nowrap), והגודל עד 7.8% מגובה המסך. מעל הצילום שכבת קריאות אלכסונית מהפינה שבה הכותרת מתחילה. המשפט והכפתורים יושבים מתחת לכותרת, בצד הפנוי, כדי שלא יצטרכו את הטריק. בטלפון אין חצייה: הטקסט למעלה והצילום רצועה מתחתיו. פתיחת העמוד (motion.md 2): ההירו מוסתר רק מאחורי html.open-anim, שהשורה הראשונה במארקאפ קובעת רק כשתנועה מותרת (בפרויקט היא עוברת ל-head). בלי JS הכל גלוי, ואם הסקריפט לא רץ ה-CSS מציג הכל אחרי 2.5 שניות. בעמוד עם הדר קובעים --t0 של 0.2 שניות כדי שההדר ייכנס ראשון, ומקצרים כך שהפתיחה כולה לא עוברת 1.2 שניות. המסך הראשון בפרויקט: min-height:100svh, תוכן ממורכז לגובה וריפוד עליון בגובה ההדר; hero-fit ו-hero-vcenter מכריעים, לא הגובה של הדמו.

קוד להדבקה

הקוד כאן עומד בפני עצמו. כל טוקן עיצוב נושא ברירת מחדל, מחלקות העזר של המאגר מוטמעות בו, ותגי הסקריפט מסודרים לפי הסדר הנכון. פרויקט שמגדיר --accent או --line משלו יורש אותם אוטומטית. הרכיב הזה מסתמך על dir="rtl".

JS

// in view = fire. Measured directly on scroll and resize, not through IntersectionObserver:
// an observer does not update while the tab is throttled (and on a real site the hero is usually
// on screen at load anyway), and an entrance that never fires leaves the hero invisible.
function inView(el,f){
  var ro;
  function chk(){
    var r=el.getBoundingClientRect();
    if(r.top<innerHeight*.9&&r.bottom>0){off();f();}
  }
  function off(){removeEventListener("scroll",chk);removeEventListener("resize",chk);if(ro)ro.disconnect();}
  addEventListener("scroll",chk,{passive:true}); addEventListener("resize",chk);
  // a layout change with no scroll (a bar above it closes, a font swaps in) can also bring it into view
  if(window.ResizeObserver){ro=new ResizeObserver(chk);ro.observe(document.body);}
  requestAnimationFrame(chk); setTimeout(chk,300);
}
function enter(root){
  var els=root.querySelectorAll(".rv");
  els.forEach(function(el,i){if(!el.style.getPropertyValue("--i"))el.style.setProperty("--i",i);});
  // a script that ran late, after the 2.5s CSS failsafe already showed the hero: keep it shown, no second entrance
  if(els.length&&getComputedStyle(els[0]).opacity==="1")root.classList.add("is-in");
  root.classList.add("rv-on");
  inView(root,function(){root.classList.add("is-in");});
}
